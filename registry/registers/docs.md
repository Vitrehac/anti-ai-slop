# Docs register

**When:** README, API docs, runbooks, technical guides, CONTRIBUTING, CHANGELOG prose.

## Voice

- Imperative and scannable.
- Second person ("run", "install") or neutral third person.
- No motivational filler.

## Constraints

- **No em dashes.** Avoid formal transitions (furthermore, moreover, additionally).
- No "Let's dive in" or "In this guide we will explore."
- Headings are labels, not marketing taglines.
- Code blocks and commands stay verbatim; only fix surrounding prose.
- Claims must be verifiable (version numbers, flags, paths).

## Structure

- Lead with what the reader can do, not why the project is exciting.
- Prerequisites before steps; steps numbered only when order matters.
- No redundant intro that repeats the H1.

## De-slop priority

1. Cut throat-clearing intros
2. Replace buzzwords with literal actions ("streamline setup" → "install in one command")
3. Merge duplicate sections
4. Keep technical precision; don't dumb down terminology the audience expects
